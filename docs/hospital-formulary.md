# รายการยาจากโรงพยาบาลและการนำเข้า XLS

ไฟล์ที่ผู้ใช้แนบตรวจพบ 827 แถวข้อมูลใน sheet `THOSxPSystemSettingPharmacyDrug` รหัสไม่ซ้ำ แต่ช่อง อยู่ในบัญชี / สถานะ / ยาหมด / ยาใช้แทน ว่างทุกแถว จึงไม่ยืนยัน active formulary หรือ stock และไม่สร้าง therapeutic equivalence จากไฟล์นี้

รุ่น 2.1 ใช้รายการ827ผลิตภัณฑ์จากไฟล์นี้เป็นบัญชียาหลักอัตโนมัติ ตามคำขอให้แทนคลังจำลอง เก็บ snapshot เฉพาะรหัส ชื่อยา ชื่อสามัญ ความแรง หน่วย ยี่ห้อ รูปแบบยา และ flags ต้นทางใน `backend/app/knowledge/hospital_formulary.json` ไม่เก็บราคา metadata ผู้จัดทำ หรือ XLS ต้นฉบับ ตัว seed โหลดเฉพาะเมื่อยังไม่มีบัญชีที่นำเข้าอยู่ จึงไม่ทับไฟล์ฉบับใหม่ที่ผู้ใช้นำเข้าแล้ว

SHA-256 ต้นฉบับ `dfe544adcd3fc1355bc452821b2481f3b19df7a761986389f3316fb0b09f3d90` ไม่มีการเปลี่ยนช่องว่างเป็น IN_STOCK ทุกผลิตภัณฑ์เริ่ม UNKNOWN ต้องตรวจคลังจริงเพิ่มเติม

## บนหน้าเว็บ

1. เข้าระบบแล้วเลือกยาได้ทันทีจาก827รายการ ไม่ต้องอัปโหลดซ้ำ หากมีไฟล์ฉบับใหม่ให้ pharmacist/admin → ฐานความรู้ยา → บัญชียาโรงพยาบาล → นำเข้ารายการยา XLS
2. เลือกไฟล์ต้นฉบับ (ไม่เกิน 8 MB); parser ไม่รันสูตรหรือ macro ตรวจหัวตาราง รหัสซ้ำ และจำนวน 1–10000 รายการก่อนบันทึกทั้งชุด
3. แพทย์ค้นชื่อยา ชื่อสามัญ ยี่ห้อ หรือรหัสได้ในพื้นที่แพทย์และหน้ายาทางเลือก แสดงความแรงและรูปแบบยาแยกตามผลิตภัณฑ์
4. เภสัชกร/admin บันทึกผลตรวจคลังเป็น IN_STOCK / OUT_OF_STOCK / UNKNOWN พร้อมเวลาและ audit ได้ เป็นสถานะที่ผู้ตรวจระบุ ยังไม่ใช่ live inventory integration

นำเข้าใหม่ด้วยไฟล์เดิมไม่เพิ่มรายการซ้ำหรือทำลายผลตรวจ stock เดิม หาก hash ต้นฉบับเปลี่ยนจะคืน stock เป็น UNKNOWN เพื่อทบทวนใหม่ รายการที่ไม่อยู่ในไฟล์ล่าสุดซ่อนจากรายการปัจจุบันแต่ยังเก็บในฐานข้อมูล

เก็บเฉพาะรหัส ชื่อยา ชื่อสามัญ ความแรง หน่วย ยี่ห้อ dosage form flags ต้นทางที่ยังไม่ตีความ แถวต้นฉบับ hash และเวลา ไม่เก็บราคา metadata ผู้จัดทำ หรือไฟล์ดิบ รายการยาไม่มี mapping ไปยัง dose rule โดยอัตโนมัติ ทะเบียนความรู้ยาเริ่มต้น10รายการยังอยู่สำหรับงานอ้างอิง แต่ไม่นำมาเป็น inventory หรือยาที่เลือกสั่งใหม่ `Drug.formulary_code` เชื่อมผลิตภัณฑ์จริงกับ `FormularyItem` โดยรหัส ไม่เดาจากชื่อสามัญ

## ข้อจำกัด deployment

เว็บ Vercel เดิมใช้ /tmp SQLite ชั่วคราว ข้อมูลนำเข้าอาจไม่อยู่ข้าม instances/cold starts จึงยังรับประกันบัญชียาร่วมกันออนไลน์ไม่ได้ ต้องตั้ง DATABASE_URL ไป PostgreSQL ของหน่วยงานที่ผ่านการอนุมัติและรัน `alembic upgrade head` ก่อนนำเข้าจริง ระบบยังใช้ demo auth จึงยังไม่รองรับ PHI หรือ production clinical workflow แม้บัญชียาเองไม่มีข้อมูลผู้ป่วย

## การยืนยันของแพทย์และกรณียาหมด

ใบสั่งใหม่ต้องเลือกผลิตภัณฑ์ที่อยู่ในบัญชีปัจจุบัน กรอกชื่อสามัญเปล่า ๆ หรือใช้ legacy synthetic drug แทนไม่ได้ เก็บรหัส/ความแรง/รูปแบบยา/source hash/สถานะคลังใน snapshot

แพทย์ยืนยันข้อเสนอของตนเองได้เมื่อสถานะ IN_STOCK หรือ UNKNOWN (UNKNOWN มีหมายเหตุชัดเจน ไม่ใช่การรับรองว่ามีของ) เฉพาะ OUT_OF_STOCK ไปคิวเภสัชกร เภสัชกรเสนอได้เฉพาะผลิตภัณฑ์ในบัญชีที่ตรวจแล้วเป็น IN_STOCK บันทึก snapshot ผลิตภัณฑ์ และตรวจ hash อีกครั้งเมื่อแพทย์เลือก หากบัญชีเปลี่ยนให้เสนอใหม่ การมีในคลังไม่ใช่ความเทียบเท่าทางการรักษา
